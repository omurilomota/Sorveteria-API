# Plano — próxima continuação do SorveteriaBackend

## Diagnóstico atual

- Projeto Spring Boot 4.1.1 com Java 21 e Maven.
- Existe um esqueleto de `Sabor` com entity, repository, service e controller, mas o fluxo REST ainda não está registrado corretamente:
  - `SaborController` ainda não tem `@RestController` nem `@RequestMapping`.
  - `SaborService` ainda não tem `@Service`.
- `Pedido` está incompleto e bloqueia a compilação em `src/main/java/com/sorveteria/model/Pedido.java:23`: `private StatusPedido();` é sintaxe inválida e o tipo `StatusPedido` não existe.
- `PedidoController` está vazio.
- O `pom.xml` declara JPA de forma manual e o `application.properties` não configura datasource; persistência real ainda precisa ser validada antes de evoluir o domínio.
- Há alterações locais e o branch `master` ainda não tem commits. Nada será commitado sem autorização.

## Próximo marco recomendado

### 1. Restaurar a compilação

1. Corrigir ou remover a linha inválida de `Pedido.java`.
2. Criar o enum mínimo `StatusPedido` somente se `Pedido` for parte deste marco.
3. Separar modelo, enum e futuros itens do pedido em arquivos próprios.
4. Rodar `./mvnw test` e tratar os erros na ordem em que aparecerem.

Critério de conclusão: o projeto compila e o teste de contexto passa.

### 2. Fazer o primeiro fluxo REST funcionar

1. Registrar `SaborService` com `@Service`.
2. Registrar `SaborController` com `@RestController` e `@RequestMapping("/sabores")`.
3. Manter `GET /sabores` e `POST /sabores` como primeiro contrato.
4. Rodar a aplicação e testar os endpoints com `curl` ou cliente HTTP.

Critério de conclusão: listar e criar sabores funciona sem depender de regras ainda inexistentes.

### 3. Validar a persistência

1. Conferir as dependências necessárias de Spring Data JPA, provedor JPA e banco local.
2. Configurar um datasource H2 apenas para desenvolvimento/teste.
3. Verificar se as entidades são descobertas e se o schema é criado corretamente.
4. Repetir os testes do fluxo de sabores após reiniciar a aplicação.

Critério de conclusão: os dados persistem durante a execução e o comportamento do banco é compreendido.

### 4. Evoluir o domínio de pedidos

1. Definir `StatusPedido`, `ItemPedido` e os relacionamentos com `Sabor`.
2. Trocar `double` por `BigDecimal` para preços e totais.
3. Criar service e controller próprios para pedidos.
4. Adicionar validações e testes para quantidade, preço, total e status.

## Ordem de trabalho

Começar pelo **marco 1**. Ele remove o bloqueio imediato e cria uma base confiável para o primeiro endpoint. Depois, concluir o marco 2 antes de adicionar pedidos ou qualquer abstração adicional.

## Validação

- `./mvnw test` após cada pequena mudança.
- `./mvnw spring-boot:run` para exercício manual dos endpoints.
- Revisar o diff antes de qualquer commit.
