# Plano — Aprendizado guiado de Spring Boot

## Objetivo

Ajudar você a evoluir o projeto **fazendo o máximo de código sozinho**. Eu atuo como mentor: explico um conceito por vez, proponho exercícios pequenos, reviso seus erros e dou pistas antes de mostrar uma solução completa. Você mantém a autoria e o controle das alterações.

## Como vamos trabalhar

1. Trabalhar em **uma etapa curta por vez**, sem tentar construir a aplicação inteira de uma vez.
2. Para cada etapa:
   - eu explico o conceito e o motivo da decisão;
   - você altera o código;
   - você executa o comando indicado;
   - você me envia o resultado ou o trecho com erro;
   - eu faço revisão, explico a causa e dou a próxima pista.
3. Eu não preciso implementar por você. Posso mostrar código completo apenas quando você pedir explicitamente ou quando um bloqueio impedir o aprendizado.
4. Cada etapa deve terminar com um comando verificável, preferencialmente `./mvnw test` ou `./mvnw spring-boot:run`.
5. Vamos valorizar código simples e legível antes de introduzir abstrações avançadas.

## Diagnóstico inicial

- O projeto ainda não possui controllers, services ou endpoints REST.
- `src/main/java/com/sorveteria/repository/Sabor.java` está no package default e contém vários records públicos; isso gera erros de compilação e não é um repositório Spring Data.
- `PedidoModel` referencia `StatusPedido` e `ItemPedido`, que ainda não existem.
- As entidades atuais misturam JPA, validação e setters amplos (`@Data`), o que pode permitir estados inválidos.
- A configuração atual usa H2 em memória, `ddl-auto=update`, console H2 e SQL visível; isso serve para aprendizado, mas não deve ser a configuração padrão de produção.
- Existe apenas um teste de carregamento do contexto.
- O `groupId` do Maven (`com.exemplo.sorveteria`) diverge dos packages da aplicação (`com.sorveteria`).
- O repositório Git ainda não possui commits; não faremos commit sem sua autorização.

## Trilha de aprendizado

### Etapa 0 — Entender o projeto e o ciclo básico

**Conceitos:** Maven, `pom.xml`, package Java, classe principal com `@SpringBootApplication`, ciclo de build e teste.

**Exercício do aluno:**

1. Executar `./mvnw test`.
2. Observar a diferença entre compilação, testes e inicialização da aplicação.
3. Identificar, sem editar, quais mensagens de erro aparecem primeiro.

**Resultado esperado:** você consegue explicar por que uma classe precisa estar no package correto e por que o Maven para ao encontrar um erro de compilação.

### Etapa 1 — Corrigir os bloqueios de compilação

**Conceitos:** package, classe pública, arquivo por tipo, entity, record, enum e referência entre classes.

**Exercício do aluno:**

1. Decidir se o conteúdo experimental de `Sabor.java` será removido, movido ou transformado em tipos separados.
2. Corrigir o package e os arquivos com erro.
3. Criar apenas os tipos mínimos necessários para `PedidoModel` compilar, se essa for a escolha de domínio.
4. Executar `./mvnw test` novamente.

**Papel do mentor:** explicar cada erro do compilador e dar uma pista, sem entregar a solução inteira de início.

**Resultado esperado:** `./mvnw test` compila e executa o teste de contexto.

### Etapa 2 — Primeiro endpoint REST

**Conceitos:** HTTP, `@RestController`, `@GetMapping`, injeção de dependência, service, response e código HTTP.

**Exercício do aluno:**

1. Criar um controller simples para listar sabores ou sorvetes.
2. Criar um service com uma lista em memória apenas para aprender o fluxo da API.
3. Retornar `ResponseEntity` e testar com curl ou navegador.
4. Executar `./mvnw spring-boot:run` e depois `./mvnw test`.

**Resultado esperado:** você entende o caminho `requisição HTTP -> controller -> service -> resposta`.

### Etapa 3 — Persistência com JPA

**Conceitos:** entity, repository Spring Data, `@Entity`, `@Table`, `@Id`, `GenerationType`, `JpaRepository`, H2 e ciclo de vida.

**Exercício do aluno:**

1. Transformar o modelo escolhido em entidade JPA.
2. Criar um repository para ela.
3. Fazer o service usar o repository em vez de uma lista em memória.
4. Testar criação, listagem e busca por id.

**Resultado esperado:** você sabe quando usar entidade e repository, e consegue explicar por que o H2 some ao reiniciar a aplicação.

### Etapa 4 — Validação e contrato da API

**Conceitos:** DTO, `@RequestBody`, `@Valid`, `@NotBlank`, `@NotNull`, `@Positive`, separação entre modelo interno e payload público.

**Exercício do aluno:**

1. Criar request/response DTOs para o endpoint.
2. Aplicar validações nos DTOs.
3. Testar payload válido, campo ausente e valor inválido.
4. Comparar resposta de validação com uma resposta de recurso não encontrado.

**Resultado esperado:** a API rejeita dados inválidos antes de tocar na regra de negócio.

### Etapa 5 — Regras de domínio e relacionamentos

**Conceitos:** agregado, associação `@OneToMany`/`@ManyToOne`, método de domínio, `BigDecimal`, invariantes e transação.

**Exercício do aluno:**

1. Modelar pedido, item e status, se esse for o próximo requisito.
2. Criar métodos como `adicionarItem` que mantenham os dois lados da associação consistentes.
3. Calcular total com `BigDecimal`.
4. Criar testes unitários para quantidade positiva, estoque e total.

**Resultado esperado:** as regras importantes vivem no domínio/service, não espalhadas no controller.

### Etapa 6 — Testes automatizados

**Conceitos:** teste unitário, teste de service, `@WebMvcTest`, `@DataJpaTest`, mocks e isolamento.

**Exercício do aluno:**

1. Testar uma regra pura de domínio.
2. Testar o controller e os códigos HTTP.
3. Testar uma operação de repository/integração com H2.
4. Rodar `./mvnw clean test`.

**Resultado esperado:** você consegue descobrir regressões antes de testar tudo manualmente.

### Etapa 7 — Organização e segurança de configuração

**Conceitos:** perfis Spring (`dev`, `test`, `prod`), variáveis de ambiente, `application-dev.properties`, H2 somente local, logs e tratamento global de erros.

**Exercício do aluno:**

1. Mover configurações locais para o perfil `dev`.
2. Criar um handler global para erros comuns.
3. Garantir que console H2 e SQL não fiquem ativos em produção.
4. Documentar os comandos e endpoints principais.

**Resultado esperado:** a aplicação continua fácil de executar localmente sem expor recursos de desenvolvimento.

## Primeiro marco recomendado

Começar pela **Etapa 1**, porque os erros atuais impedem qualquer aprendizado confiável sobre controllers e persistência. O marco é:

- projeto compila;
- todos os tipos estão em packages corretos;
- `./mvnw test` passa;
- você consegue explicar o que foi corrigido e por quê.

Depois disso, construiremos **um único endpoint GET** na Etapa 2.

## Critérios de aprendizado

- Você consegue explicar, com suas palavras, a diferença entre controller, service, entity, repository e DTO.
- Você consegue interpretar os primeiros erros do Maven e do Spring.
- Cada mudança é pequena, testável e reversível.
- O código usa `BigDecimal` para dinheiro e não `double`.
- Não há exposição direta de entidades como contrato público da API.
- Configurações locais não viram configuração de produção.

## Preferências confirmadas

- Você quer aprender e implementar a maior parte sozinho.
- A abordagem será progressiva, com exercícios e revisão, não uma implementação completa feita pelo mentor.
- Podemos manter H2 no início porque ele reduz a infraestrutura necessária para aprendizado.
